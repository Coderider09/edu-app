# Архитектура

## Backend

Модульный монолит на FastAPI. Модули (контент, тестирование, рейтинги) разделены на уровне роутеров и сервисов, поэтому любой из них можно вынести в отдельный сервис без переписывания (ТЗ, п. 11).

```
api/v1/*.py        HTTP: валидация (Pydantic), авторизация, сериализация (serializers.py — локализация tj/ru)
services/*.py      бизнес-логика
  testing.py       подбор вопросов, попытки, проверка ответов, таймер, завершение
  gamification.py  баллы, серии, уровни, ежедневный стрик, достижения, шкала ММТ
  progress.py      прогресс по предметам и темам (раздельно по ролям)
  leaderboard.py   рейтинги, кэш в Redis
  cache.py         Redis с запасным вариантом в памяти (кэш + rate limit)
models/*.py        SQLAlchemy 2.0; enum хранятся как VARCHAR (переносимые миграции)
admin/             SQLAdmin, роли content_manager / superadmin
```

### Ключевые решения

- **Роли.** Таблица `user_roles` позволяет пользователю иметь обе роли; `users.active_role` определяет текущую ветку. Попытки (`test_attempts.role`), баллы (`points_ledger.role`) и прогресс уроков хранятся с ролью, поэтому прогресс раздельный.
- **Иерархия контента.** `Topic.parent_topic_id`: корневая тема — раздел/четверть, дочерние — темы. У раздела есть итоговый тест (`section_test`) по вопросам всех дочерних тем.
- **Вопросы.** Один `Question` принадлежит теме (тест по теме), уроку (`lesson_id` — мини-проверка) или тесту ММТ (`exam_test_id`, плюс `subject_id` для разбивки по предметам). В тесты по теме, разделу и в тренировку идут только вопросы темы (`topic_pool()`).
- **Язык контента.** Уроки и вопросы хранятся с полем `language`. Выдаётся язык обучения школьника или язык интерфейса; если на нужном языке ничего нет — другой язык. Названия кластеров, предметов и тем хранятся в полях `title_ru` / `title_tj`.
- **Экзаменационный режим.** В ответах на вопросы ММТ нет правильного варианта и объяснения; баллы начисляются при завершении. Порядок вопросов фиксирован, время проверяется на сервере (15 с допуска на задержку сети).
- **Защита от накрутки.** Бонус за завершение теста начисляется только за первое прохождение; на один вопрос в попытке можно ответить только раз (ограничение уникальности в БД).
- **Попытки можно продолжить.** Незавершённая попытка того же теста возвращается снова; просроченная закрывается автоматически.
- **Офлайн-пакеты** (`services/packs.py`). Один ZIP на предмет: `content.json` (темы, уроки, вопросы с ключами и объяснениями, структура субтеста) и `images/*.webp`. Вопросы фиксированных тестов ЦВЭ в пакеты не входят. Версия — хэш содержимого; содержимое кэшируется на час и сбрасывается при любом изменении в админке. ZIP собирается при первом скачивании в `PACKS_DIR` (в Docker — том `packs_data`).
- **Синхронизация** (`services/sync.py`, `POST /sync`). Приложение присылает попытки с `client_id`, ответами и временем ответа. Сервер не доверяет клиентской проверке: каждый ответ снова проверяется `grade()`, баллы, серия ×1,5, бонусы и достижения считаются так же, как онлайн, в порядке времени ответов. Время ограничено: не в будущем и не раньше чем 60 дней назад; ответы пробного ЦВЭ после окончания времени отбрасываются. Повторная отправка возвращает ту же попытку (`uq_attempt_user_client`). Ежедневная серия учитывает дни, когда ученик занимался офлайн; поздняя загрузка более старого дня серию не сбрасывает.

## Mobile

```
config/     AppConfig (URL API, хранилища), router (go_router + redirect по состоянию сессии)
core/       ApiClient (Dio: JWT + обновление токена, кэш GET-ответов в Hive при отсутствии сети),
            Strings (tj/ru), AppTheme (палитры веток), motion (упрощение анимаций при низком FPS),
            общие виджеты (Skeleton, AnimatedProgressBar, Shake, FlyingPoints, MarkdownView)
data/       модели и репозитории
features/   экраны; состояние — Riverpod (Notifier / FutureProvider)
```

- **Сессия** (`SessionController`): loading → loggedOut → needsRole → ready. Маршрутизатор перенаправляет по этому состоянию (выбор роли пропустить нельзя).
- **Офлайн.** GET-ответы (дашборд, уроки, темы) кэшируются. Попытка теста сохраняется в Hive и продолжается без сети; ответы, данные офлайн, ставятся в очередь и отправляются перед следующим ответом или при завершении.
- **Смешанный режим** (`lib/offline/`):
  - `PackStore` скачивает пакеты с экрана «Офлайн-материалы» (`/downloads`) и распаковывает их в фоновом изоляте в хранилище приложения.
  - `engine.dart` — копия серверных правил: проверка трёх типов заданий, очки, серия, пересчёт в 500 баллов, подбор вопросов, включая пробный ЦВЭ по структуре кластера из манифеста.
  - `OfflineTesting` проводит попытку на телефоне, если нужные пакеты скачаны, и отдаёт JSON того же вида, что сервер, поэтому экраны теста и результата общие. Локальные попытки имеют отрицательный id.
  - `SyncService` отправляет готовые попытки, прочитанные уроки и отметки: при входе, при возвращении в приложение, после теста и раз в 2 минуты, пока очередь не пуста.
  - Без сети экраны предмета, темы и урока строятся из пакета.
  - Официальные образцы ЦВЭ и «Повторить ошибки» работают только онлайн.
- **Слабые устройства.** `FrameRateMonitor` измеряет время кадров; если больше 30 % кадров медленнее 25 мс, отключаются конфетти, «летящие» баллы и shimmer, а длительности анимаций сокращаются. То же можно включить вручную в настройках.
