# Образовательная платформа для абитуриентов и школьников (Таджикистан)

**Версия документа:** 1.0
**Дата:** сентябрь 2026
**Статус:** для передачи в разработку (агент Devin)

---

## 1. Общее описание проекта

### 1.1 Идея
Мобильное приложение (кроссплатформенное, Android/iOS) с backend на Python, объединяющее две независимые образовательные ветки под одной платформой:

1. **Абитуриенты** — подготовка к вступительным экзаменам (ММТ / национальное тестирование), разделённая на 5 кластеров направлений.
2. **Школьники** — обучение по школьной программе: уроки, тесты, вопросы по всем предметам.

Пользователь выбирает свою роль **при регистрации** и получает интерфейс, адаптированный под его цели.

### 1.2 Цель проекта
Дать доступ к структурированному, качественному учебному контенту с игровым элементом (баллы, прогресс, достижения), чтобы:
- абитуриенты могли системно готовиться к ММТ, тренируясь на тестах прошлых лет;
- школьники могли закрывать пробелы по предметам школьной программы;
- обучение было вовлекающим за счёт дизайна, анимаций и системы прогресса.

### 1.3 Целевая аудитория
- Абитуриенты 10–11 классов и выпускники прошлых лет, готовящиеся к поступлению в вузы Таджикистана.
- Школьники 1–11 классов.
- (Потенциально, вне MVP) родители, отслеживающие прогресс ребёнка.

## 2. Роли пользователей и регистрация

### 2.1 Общий флоу регистрации
1. Экран приветствия (Splash + Onboarding, 3 слайда с анимацией — что умеет приложение).
2. Экран регистрации: email/телефон + пароль, ИЛИ вход через Google.
3. **Обязательный шаг выбора роли** (нельзя пропустить, нельзя сменить роль без обращения в поддержку/настройки):
   - Карточка "Я абитуриент 🎓"
   - Карточка "Я школьник 📚"
4. В зависимости от выбора — доп. анкета:

**Если "Абитуриент":**
- Год поступления (текущий / прошлый / через год)
- Выбор кластера направления (см. п.3.1) — можно выбрать 1 основной + отметить интерес к запасному
- Регион (для локальной статистики/рейтинга по регионам — опционально)

**Если "Школьник":**
- Класс (1–11)
- Школа (текстовое поле, необязательно)
- Язык обучения (таджикский/русский) — влияет на язык контента

5. Экран "Профиль создан" с анимацией → переход на главный экран (Dashboard) своей ветки.

### 2.2 Смена роли / мультиаккаунтность
- В настройках профиля должна быть возможность добавить вторую роль на тот же аккаунт (например, школьник, который параллельно уже готовится к ММТ) — переключатель ролей в профиле, данные и прогресс хранятся раздельно по каждой роли.

## 3. Раздел "Абитуриенты"

### 3.1 Структура: 5 кластеров ММТ
Внутри раздела абитуриента — 5 кластеров (направлений), соответствующих официальной структуре национального тестирования Таджикистана. Точный список предметов в каждом кластере нужно сверить с актуальным положением Маркази миллии тестирование на год запуска, примерная база для ТЗ:

| Кластер | Условное направление | Пример предметов |
|---|---|---|
| Кластер 1 | Технический / инженерный | Математика, Физика, Таджикский/Русский язык |
| Кластер 2 | Естественно-научный / медицинский | Биология, Химия, Таджикский/Русский язык |
| Кластер 3 | Гуманитарный | История, Обществознание, Таджикский/Русский язык |
| Кластер 4 | Экономический / юридический | Математика, Обществознание, Таджикский/Русский язык |
| Кластер 5 | Филологический / языковой | Иностранный язык, Таджикский язык, Литература |

> ⚠️ Пункт для уточнения перед разработкой: точное официальное название и состав каждого из 5 кластеров и перечень предметов внутри — должны быть провалидированы с актуальным документом Национального центра тестирования РТ. В коде и БД предметы/кластеры должны быть **не захардкожены**, а храниться как отдельные сущности, редактируемые через админку.

### 3.2 Что находится внутри каждого кластера
После выбора кластера пользователь попадает на экран кластера, где видит:

1. **Предметы кластера** (карточки, обычно 2–3 предмета) — вход в предмет.
2. **Полные тесты ММТ прошлых лет** — по годам (например, 2020, 2021, ..., 2025), в формате "как на настоящем экзамене": фиксированное время, фиксированное количество вопросов по всем предметам кластера сразу, без пауз.
3. **Тренировочный режим по предмету** — тесты только по одному предмету, без ограничения времени, с объяснением после каждого ответа.
4. **Уроки/теория** — структурированные конспекты, видео (если есть), примеры решений по темам предмета.
5. **Рейтинг** — позиция пользователя среди всех готовящихся в этом кластере (по накопленным баллам/точности).

### 3.3 Внутри предмета (Абитуриент)
Иерархия: **Кластер → Предмет → Раздел темы → Тема → (Урок | Тест)**

- **Урок**: текст + формулы/изображения + опциональные примеры разбора задач + мини-проверка в конце (3–5 вопросов).
- **Тема-тест**: набор тестов по конкретной теме (10–20 вопросов), с таймером или без — на выбор пользователя.
- **Тест ММТ прошлых лет**: отдельный immutable-набор вопросов, привязанный к конкретному году и кластеру, воспроизводит реальный формат экзамена.

### 3.4 Формат вопроса теста
- Одиночный выбор (4–5 вариантов ответа) — основной формат ММТ.
- (Опционально на будущее) вопросы с вводом числового ответа для математики.
- К каждому вопросу: правильный ответ + развёрнутое объяснение, которое показывается ПОСЛЕ ответа пользователя (не до).
- Возможность отметить вопрос как "сложный"/"на повтор" (аналог избранного) — такие вопросы попадают в отдельную подборку "Повторить ошибки".

## 4. Раздел "Школьники"

### 4.1 Структура
Иерархия: **Класс → Предмет → Четверть/раздел → Тема → (Урок | Тест | Вопросы)**

- Список предметов зависит от класса (например, для 1–4 класса — базовый набор, для 9–11 — расширенный, включая профильные предметы).
- Список предметов и их наполнение по классам — должны быть настраиваемыми через админку, а не захардкожены.

### 4.2 Внутри предмета (Школьник)
- **Уроки**: конспект темы + иллюстрации/схемы.
- **Тесты по теме**: 5–15 вопросов на закрепление сразу после урока.
- **Вопросы для самопроверки** (короткие, устные по формату — с открытым текстовым ответом, который сверяется с эталоном пользователем самостоятельно, без строгой авто-проверки) — опционально в MVP, либо перенести на фазу 2.
- **Итоговый тест по разделу/четверти** — обобщающий, больше вопросов, влияет на прогресс по предмету.

## 5. Система баллов, оценок и прогресса

### 5.1 Начисление баллов
- За каждый правильный ответ — базовые баллы (например, 10 очков).
- Бонус за серию правильных ответов подряд (streak) — множитель баллов (например, x1.5 после 5 подряд).
- Штраф/0 баллов за неправильный ответ (жизни/сердца не отнимаются — свободный режим обучения, чтобы не отпугивать).
- За прохождение полного теста ММТ прошлых лет — дополнительный бонус + расчёт "примерного балла ММТ" по официальной шкале (100–200 баллов), чтобы пользователь понимал, на какой результат он бы вышел на реальном экзамене.

### 5.2 Уровни и достижения (геймификация)
- Система уровней пользователя (Новичок → Ученик → Продвинутый → Эксперт → Мастер), основанная на суммарных баллах.
- Достижения (бейджи): "Первый тест пройден", "7 дней подряд", "100% в тесте", "Все темы кластера пройдены" и т.д.
- Ежедневный стрик (streak) захода/занятий — визуальный счётчик как в Duolingo.
- Прогресс-бар по каждому предмету/теме (% пройденного материала).

### 5.3 Профиль пользователя
Профиль должен отображать:
- Аватар (набор готовых иконок для выбора, без загрузки фото на MVP — упрощает модерацию).
- Имя, класс/кластер, уровень, общий счёт баллов.
- График/диаграмма прогресса по предметам (radar chart или горизонтальные бары).
- История последних пройденных тестов с результатами.
- Список полученных достижений.
- Позиция в общем/локальном рейтинге (лидерборд).
- Настройки: язык интерфейса (тадж./рус.), уведомления, смена роли, тема (светлая/тёмная).

## 6. Дизайн и UX

### 6.1 Общие принципы
- Современный, "чистый" дизайн в духе лучших EdTech-приложений (Duolingo, Quizlet, Khan Academy) — крупные карточки, много воздуха, минимум текста на экране.
- Разная акцентная цветовая палитра для веток "Абитуриент" (например, синий/фиолетовый — строгость, экзамен) и "Школьник" (например, оранжевый/зелёный — дружелюбие, игра) — помогает пользователю ощущать разницу режимов.
- Поддержка светлой и тёмной темы.
- Локализация: таджикский и русский язык интерфейса и контента (переключение в настройках).

### 6.2 Анимации (обязательный пункт по запросу)
- Анимация перехода между экранами (плавный slide/fade).
- Анимация правильного/неправильного ответа в тесте (например, зелёная вспышка + вибрация на "верно", лёгкое покачивание на "неверно").
- Анимация начисления баллов (числа "взлетают" к счётчику баллов в углу экрана).
- Анимация прогресс-бара (плавное заполнение, а не мгновенный скачок).
- Конфетти/праздничная анимация при завершении теста с высоким результатом или получении достижения.
- Skeleton-loading (мерцающие плейсхолдеры) вместо простых спиннеров при загрузке контента.

### 6.3 Ключевые экраны (для будущего макета)
1. Splash / Onboarding
2. Авторизация / регистрация
3. Выбор роли
4. Анкета (кластер / класс)
5. Dashboard абитуриента (кластеры, прогресс, быстрый доступ к последнему тесту)
6. Dashboard школьника (предметы по классу, прогресс)
7. Экран предмета (список тем/уроков/тестов)
8. Экран урока (контент + мини-тест в конце)
9. Экран прохождения теста (вопрос + таймер + варианты)
10. Экран результата теста (баллы, разбор ошибок, кнопка "Повторить ошибки")
11. Профиль
12. Рейтинг/лидерборд
13. Настройки

## 7. Технический стек

### 7.1 Backend
- **Язык/фреймворк:** Python 3.12+, FastAPI
- **База данных:** PostgreSQL (основные данные)
- **Кэш/сессии:** Redis (кэш рейтингов, сессии, rate limiting)
- **Очереди (при необходимости):** Celery + Redis/RabbitMQ — для фоновых задач (пересчёт рейтингов, отправка уведомлений)
- **Аутентификация:** JWT (access + refresh токены), OAuth2 (Google) как опция
- **Файловое хранилище:** S3-совместимое хранилище (для изображений уроков, аватаров-иконок, возможных видео) — например, MinIO для self-hosted варианта
- **Контейнеризация:** Docker + docker-compose для локальной разработки; манифесты для деплоя (Docker Swarm или Kubernetes — по решению на этапе инфраструктуры)
- **Документация API:** автогенерация через FastAPI (Swagger/OpenAPI) — обязательно
- **Тесты:** pytest, покрытие ключевой бизнес-логики (начисление баллов, проверка ответов, генерация тестов)

### 7.2 Mobile Frontend
- **Фреймворк:** Flutter (единая кодовая база Android + iOS)
- **State management:** Riverpod или Bloc (на усмотрение агента разработки, зафиксировать один подход)
- **Локальное хранилище:** Hive/SQLite для офлайн-кэша уроков и незавершённых тестов (частичная поддержка слабого интернета — актуально для регионов Таджикистана)
- **Анимации:** встроенные Flutter-анимации (AnimationController, Hero-переходы) + Lottie для сложных анимаций (конфетти, маскот)
- **Push-уведомления:** Firebase Cloud Messaging (напоминание о ежедневном стрике, новых тестах)

### 7.3 Инфраструктура и DevOps
- CI/CD: GitHub Actions (линт → тесты → сборка → деплой)
- Мониторинг: базовый — логирование + healthcheck эндпоинты; продвинутый — Prometheus/Grafana (может быть фазой 2)
- Хостинг backend: VPS с Docker-compose на старте (для MVP), с возможностью миграции на облако (AWS/GCP) при росте нагрузки

## 8. Структура базы данных (укрупнённо)

### 8.1 Основные сущности

```
User
- id, email/phone, password_hash, name, avatar_id
- role (abiturient | schoolboy) -- может быть массивом при мультиролях
- language (tj | ru)
- created_at, last_login_at

AbiturientProfile
- user_id (FK)
- cluster_id (FK -> Cluster)
- target_year
- region

SchoolProfile
- user_id (FK)
- grade (1-11)
- school_name
- language_of_study

Cluster
- id, name, description, order

Subject
- id, name, cluster_id (nullable, FK -> Cluster, для абитуриентских предметов)
- grade (nullable, для школьных предметов конкретного класса)

Topic
- id, subject_id (FK), title, order, parent_topic_id (nullable, для вложенности)

Lesson
- id, topic_id (FK), title, content (markdown/rich text), media_urls[], order

Question
- id, topic_id (FK, nullable если это вопрос из архивного теста ММТ)
- exam_test_id (FK, nullable, если вопрос принадлежит тесту прошлых лет)
- text, options[] (json), correct_option_index, explanation, difficulty

ExamTest  -- тесты ММТ прошлых лет
- id, cluster_id (FK), year, duration_minutes, total_questions

TestAttempt
- id, user_id (FK), test_type (topic_test | exam_test | lesson_check),
  reference_id (topic_id или exam_test_id), started_at, finished_at,
  score, correct_count, total_count

UserAnswer
- id, attempt_id (FK), question_id (FK), selected_option_index,
  is_correct, answered_at

PointsLedger
- id, user_id (FK), points, reason (correct_answer | streak_bonus | achievement | test_completion),
  created_at

Achievement
- id, code, title, description, icon

UserAchievement
- id, user_id (FK), achievement_id (FK), unlocked_at

Leaderboard (материализованное представление / кэш в Redis)
- user_id, cluster_id или grade, total_points, rank, period (weekly | all_time)
```

> Примечание для разработчика: схема выше — концептуальная. Перед реализацией миграций (Alembic) агент должен уточнить типы полей, индексы (особенно на `user_id`, `topic_id`, `cluster_id` для быстрых выборок) и связи many-to-many там, где пользователь может проходить несколько кластеров.

## 10. Админ-панель (обязательный модуль)

Без админки контент невозможно поддерживать, поэтому это не опционально:

- Отдельная веб-панель (можно на FastAPI + готовый admin-фреймворк, например SQLAdmin, либо отдельное React/Vue SPA).
- Функции: CRUD по кластерам, предметам, темам, урокам, вопросам, тестам ММТ прошлых лет; управление пользователями (бан/разбан); просмотр общей статистики (DAU, количество пройденных тестов, средний балл по кластерам).
- Роли внутри админки: контент-менеджер (только контент) и суперадмин (полный доступ).

## 11. Нефункциональные требования

- **Производительность:** ответ API на большинство запросов < 300 мс при нагрузке до 1000 одновременных пользователей (ориентир для MVP).
- **Офлайн-режим:** уроки и уже загруженные тесты должны быть доступны для просмотра без интернета (частичный офлайн через локальный кэш Flutter).
- **Безопасность:** хэширование паролей (bcrypt/argon2), защита от брутфорса (rate limiting на /auth/login), валидация всех входных данных.
- **Масштабируемость:** архитектура backend должна позволять вынести отдельные модули (контент, тестирование, рейтинги) в отдельные сервисы при росте нагрузки, без переписывания с нуля.
- **Локализация:** весь пользовательский текст (UI-строки и контент уроков/вопросов) должен храниться с привязкой к языку (tj/ru), чтобы не хардкодить перевод в коде.
- **Доступность на слабых устройствах:** приложение должно корректно работать на бюджетных Android-устройствах с 2 ГБ RAM (частая ситуация в регионе) — избегать тяжёлых анимаций на слабом железе (деградация анимаций при низком FPS).

## 12. Этапы разработки (предлагаемый Roadmap)

**Фаза 1 — MVP (ядро)**
- Регистрация, выбор роли, анкета
- 1 кластер полностью наполнен (для теста гипотезы) + школьная ветка для 2–3 классов
- Прохождение тестов по теме, начисление баллов, простой профиль
- Backend + Docker + базовое CI
